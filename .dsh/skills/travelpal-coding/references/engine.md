# VNS 引擎编码规范（TravelPal engine）

> 改 VNS / 优化引擎（TSPTW 元启发式算法、适应度、VNS 默认参数）时的规范。独立于一般后端代码，因为改引擎参数与改常规 API 是两类活。引擎属"确定性算法模型"（相对 LLM 融合的"概率模型"）。

## 算法背景（理解 Why）

- 项目核心是 **TSPTW（带时间窗旅行商）+ 元启发式优化**，与 **LLM 融合**（概率模型）相对，引擎这一侧是**确定性算法**。
- 用 **VNS（可变邻域搜索）** 主循环：shaking（扰动跳出局部最优）→ VND 局部搜索。
- 关键点：**参数不是玄学，每个参数都有设计意图**（决定搜索深度、收敛速度、扰动强度）。改参数要先理解意图，不能盲调。

## VNS 默认参数（改前先读设计意图）

| 参数 | 作用 | 建议/说明 |
|------|------|-----------|
| `max_iter` | 主循环迭代次数，决定搜索深度 | 100-300；越大越充分、越耗时 |
| `shaking_neighbors` | 抖动强度候选集合大小 | 越大扰动越剧烈，利于跳出局部最优 |
| `no_improve_limit` | 连续无改善阈值，控制早停 | 越小越早收敛 |
| `sa_initial_temp` / `sa_cooling_rate` | SA 接收准则退火速度 | 控制解接受概率演变 |
| `elite_size` | 精英池容量 | 保留历史上最优结构 |
| `final_vnd_rounds` | 主循环后对精英解额外 VND 轮数 | 提升最终解稳定性 |

- 每项在代码里有 `# ----------` 段注释 + 设计说明，改参数必须同步更新这些注释。

## 注释要求（引擎用 P3 详尽档）

- 引擎核心函数达 **P3**：逐行解释算法与数学推导。
- 关键数学推导、索引映射、算子效果，用行内注释讲 **Why**（见 SKILL.md 行内注释原则）。

## 具体示例（照此风格写）

```python
# 连续无改善计数递增，用于触发早停（避免无效迭代）
no_improve += 1

# 自适应机制：让历史上更有效的算子获得更高被选中概率，加速收敛
self.operator_weights[self.last_operator] *= 1.02

# VND 按 swap → inversion → insert → 2opt 顺序执行（经验排序，前期收敛最快）
self._local_search(sol, dis_matrix, 'swap')

# 删除景点后索引不连续，重新映射为 0,1,2... 对齐矩阵维度
mapping = {old: new for new, old in enumerate(sorted(remaining))}
```

- 行内注释用 **Why** 不用 **What**（反例：`no_improve += 1` 不写注释）。

## 约束

- 引擎代码用 `np.ndarray`，关键矩阵在 docstring 补维度说明。
- 单函数长度软约束 120 行（核心算法放宽）。
- 稳定性和收敛性优先于代码简洁——引擎是算法逻辑，改动要谨慎、可解释。
