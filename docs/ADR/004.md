# ADR-004: 营业时间 LLM 解析与 Agent 架构决策

## 元信息

| 项 | 值 |
|----|----|
| 作者 | xiaojiune |
| 生效日期 | 2026-07-18 |
| 标签 | `LLM / Agent` |
| 复审触发 | 解析失败率显著上升 / LLM 成本超出预算时 |
| Supersedes | 无 |

## 状态

**Accepted**。

用 LLM 直接解析高德营业时间（opentime2），放弃规则增强方案；MVP 阶段维持手写 Function Calling，暂不上 MCP。

## 执行摘要

- 高德 POI 返回的营业时间格式极其复杂（季节分段/节假日特例/闭馆日/跨午夜等），规则引擎每覆盖一种变体都要加正则分支，且无法泛化未知格式。
- 本决策改用纯 LLM 解析：覆盖无限格式变体，单次成本约 0.00005 元，失败时返回 None 回退。
- 同时在做 LLM 调用前用日期/节假日前置计算，降低 LLM 理解负担。
- MVP 阶段工具数少，维持手写 Function Calling；MCP 作为后续迁移预留（见 ADR-005）。

**Y-Statement**：在"营业时间格式无限、需低成本稳健解析"的场景下，我们选择纯 LLM 解析 + 规则兜底，以换取覆盖广、成本低，接受"依赖 LLM 可用性与毫秒级延迟"。

## 背景

高德 POI 返回的 `opentime2` 字段格式极其复杂，规则解析难以覆盖全部变体：

| 格式变体 | 示例 | 规则解析难度 |
|---------|------|------------|
| 季节分段 | `04/01-10/31 08:30-17:00；…` | 高 |
| 节假日特例 | `春节,劳动节 08:30-17:00` | 极高 |
| 闭馆日 | `周一 全天不开放` | 中 |
| 停止入园 | `08:30-17:00,17:00停止入园` | 中 |
| 24小时 | `00:00-24:00` | 低 |
| 跨天 | `20:00-02:00` | 中 |
| 空/无意义 | `暂无营业时间` / `""` | 低 |

规则引擎每覆盖一种变体都需新增正则分支，且无法泛化未知格式。

## 决策

### 决策 1：纯 LLM 解析

采用 LLM 直接解析营业时间，放弃规则增强。原因：格式变体无限，规则引擎永远追不上；LLM 成本极低；失败返回 None 无风险，由前端用默认值兜底。

### 决策 2：日期/节假日前置计算

在调用 LLM 前，用日期与节假日库提前算出当天日期、星期、是否法定节假日，注入 prompt，减小 LLM 理解负担。跨午夜营业时间截断到当天 24:00，由 prompt 约束。

### 决策 3：MVP 不上 MCP

维持手写 Function Calling。工具数少时 MCP 协议带来额外复杂度而无收益，等工具数增长到阈值再增量迁移（见 ADR-005）。

## 备选方案

### 方案 A：纯 LLM 解析

覆盖无限格式变体，成本极低，失败回退零风险。

**否决**：无——采纳本方案。

### 方案 B：规则增强

无外部依赖、零延迟。

**否决**：格式变体无限，维护成本持续增长，总有未覆盖边界 case。放弃。

### 方案 C：规则 + LLM 混合

常见格式走规则、兜底走 LLM。

**否决**：两套逻辑增加维护复杂度，规则覆盖的边际效益递减。不推荐。

## 后果

**正面**：

- 覆盖营业时间的无限格式变体。
- 单次成本极低（约 0.00005 元量级）。
- 解析失败返回 None，前端兜底默认值，无硬失败。

**负面**：

- 依赖 LLM API 可用性。
- 引入毫秒级解析延迟。

**中性**：

- 维持手写 FC，工具数增长后再迁 MCP。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| LLM 返回非法 JSON / 越界时间 | 解析失败 | 返回 None + 前端默认值兜底 |
| LLM 不可用 | 营业时间缺失 | 前端回退默认营业时间 |
| 跨午夜/节假日解析偏差 | 时间窗不准 | prompt 前置注入日期/节假日 + 截断约束 |

## 复审条件

- 解析失败率显著上升时，评估是否引入规则混合层或 VCR 回归。
- 营业时间解析成为瓶颈时，评估本地缓存。
