## 状态

**✅ 已采纳**——作为前端技术债基线清单，配合 ADR-009 组件库迁移与 ADR-008 架构演进渐进清理。

## 背景

前端经历三轮大改造：Naive UI 分步迁移（ADR-009）、品牌色板 + 卡片 token 落地、Agent 全局面板化（AgentPanel/ChatStream/PendingPanel）。架构骨架已稳定，本 ADR 做一次全貌评估，对照后端 ADR-010 格式记录**已消解项**与**剩余隐忧**。

## 总体评估

结构与后端同构地清晰：pages / components / composables / stores / services / types 分层职责到位，Naive UI 迁移主体完成（alert/prompt/confirm 零残留）、品牌 token 化全站落地、strict 类型 + eslint + prettier 全绿。**主要矛盾集中在「清理性技术债」（类型重复、死代码、失效样式）与「健壮性缺口」（SSE/轮询/地图失败路径），而非结构性缺陷**。

### 做对的地方

1. **分层职责清晰**：页面（pages）薄、逻辑进 composable（usePoiSearch/useEditTable/useTaskPolling/useTypewriter）、共享状态集中 store、API 收敛 services。SSE 打字机（ChatStream）、地图渲染（AmapMap）、编辑表格（useEditTable）抽象各自内聚。
2. **Agent 面板化收敛**：数据流单向清晰——`ChatStream emit(tool-result) → AgentPanel 转 store.addPendingPoi → PendingPanel 读 store`，对话/浮层/待选三方职责分离，store 全局共享待选素材。
3. **品牌系统落地**：theme.ts 单一事实来源（品牌色 + 语义色 + 中性色 + 卡片 token），全站手写样式走 `--tp-*` 变量；功能色板（地图 8 色）与品牌板分离合规。
4. **工具链健康**：`strict: true` 类型检查、eslint + prettier + vue-tsc 纳入 check，gen:api（OpenAPI 同步）已作为 check 一步（确保 types.generated.ts 不漂移）。
5. **卡片 token 复用**：四页卡片 + 待选卡片 + Agent 面板统一米白暖底 + 青绿细边框 + 极淡阴影 + hover 抬升（ADR-009 §4 落地）。

### 已消解项

- **启程时间 0=午夜误拦（高）**：`if (!store.dayStart)` 将默认 0（合法午夜）当「未填写」拦截。改为 `dayStartConfirmed` 状态 + 未确认时 dialog 提示当前值 +「我已知晓」放行，确认后本会话不再问、改值需重新确认。
- **.npmrc Windows 残留（高）**：`cache=C:\tmp\npm-cache` 指向 Windows 绝对路径并遗留 83MB 缓存目录，已删除，恢复 Linux 默认 npm 缓存。

## 技术债清单

### 1. 类型单一来源漂移（中，对应 ADR-010 #9 前端侧）

- `services/api.ts` 的 `TaskDetail`/`HistorySummary`/`HistoryListResponse`/`HistoryDetail` 四接口与 `types.generated.ts` 逐字段重复手工定义——gen:api 已纳入 check，但重复声明绕过了生成产物。
- `types.ts:7-10` `PlanRequestPayload` 用 `& { cost_matrix?; dist_matrix? }` 扩展，而 generated 的 `PlanRequest` 已含这两个字段，重复扩展掩盖生成类型更新。
- `types.ts:82` `ScheduleItem.stay: number` 与后端 `typedefs.py` 的 `stay: str` 漂移（实证案例）。

> 处置：重复接口直接 import generated 类型；删 PlanRequestPayload 交集；ScheduleItem.stay 统一类型或标注。长期按 ADR-010 #9 走 OpenAPI schema 单一来源。

### 2. store 组织（中）

- `reset()` 漏清 `pendingPois`/`loading`/三个惩罚权重；且 reset 无调用方（grep 全站仅注释命中），是「清空会话」预留的死方法。
- `suggestSpots`/`suggestCostMatrix`/`suggestDistMatrix`/`suggestPolylines`/`suggestAlgoTime` 五个「suggest 响应缓存」字段混入全局 store，实际只被 HomePage→SuggestPage 跨页传递消费。
- `addSpot()` 接受 `SpotFormItem & { poi_type?: string }` 双形状，酒店/景点分支靠运行时字段判定，类型无约束。

> 处置：reset 补全清空（pendingPois/loading 必加）或删除 reset；suggest 缓存可提 `useSuggestCache()` composable；addSpot 拆 `addHotel`/`addSpot` 或定型 union。

### 3. 健壮性缺口（中）

| 位置 | 问题 | 处置 |
|------|------|------|
| ChatStream.vue | SSE fetch 无 AbortController，AgentPanel `v-if="show"` 销毁后 fetch 仍运行、闭包写已卸载组件 ref；无断线重连 | 卸载时 `controller.abort()`；fetch 失败给重试 |
| useTaskPolling.ts | 轮询无超时上限，任务永久 running 无限轮询；单次网络异常直接 reject | 加最大时长（约 5min）+ 超时 reject；抖动时跳过本次 |
| AmapMap.vue | `loadAmapScript()` 无 onerror，key 失效/断网时 Promise 永不 resolve 地图白屏；5 处 `console.log('[map]')` 调试残留 | script.onerror 时 reject → 错误占位；清调试日志 |
| HistoryPage.vue | 删除当前页最后一条后 `page` 不回退落空页 | 删后 `items 空 && page>1 → page--` 再 load |
| api.ts | axios 零拦截器/零超时，错误处理散落且写法不一（`(e as any)?.response?.data?.detail` 两处重复） | 统一 response/error 拦截器 + timeout |

### 4. 死代码与重复（低）

- **死代码**：`postChat`（Agent 化后废弃）、`store.reset`、`POILookupItem` 类型、`useTypewriter.start`（ChatStream 只用 append/reset）、`SchedulePanel.statusClass`（无操作函数，docstring 与实现不符）。
- **重复**：5 处近似卡片样式（bg-card+border+阴影+hover）→ 提 `.tp-card` 公共类；3 处分钟→HH:MM 格式化（SchedulePanel.fmt / PlanPage.fmtParamTime / useEditTable.formatBiz）→ `utils/time.ts`；2 处错误提取 → 统一 util。

### 5. 失效样式（低）

- `SchedulePanel.vue .row-highlight`（模板无对应类）、`SuggestPage.vue .empty-state .btn`（空态用 n-button）。
- `theme.ts` 7 个 token（`--tp-primary-hover`/`primary-text`/`success-soft`/`warning-soft`/`info`/`info-soft` 等）定义后全站零引用（dark 预留 3 个豁免）。
- 硬编码 `color: #fff` ×2（PendingPanel:105 / ChatMessage:62，主色按钮白字）。

### 6. 工具链（低）

- `typescript ^6.0.3` 与 `openapi-typescript 7.13.0` 的 peerDependencies `^5.x` 存在 ERESOLVE 冲突（npm install 警告，gen:api 环境与声明不符）。
- `vfonts` 依赖全项目零引用，冗余。
- `frontend/C:\tmp\npm-cache` 83MB 已删（✅）；`tsconfig include` 未含 `components.d.ts`（vue-tsc 经 .vue 引用间接生效，可保留）。

### 7. 观察项（非债）

- `.main-content padding-left:160px`——与左侧待选栏的分割间距，用户主动设计，保留。
- `keep-alive` 全量缓存 4 页——Suggest/Plan 纯展示 store 数据，PlanPage 组件内状态（showMap/highlight）切换保留，依赖 `watch(planResult)` 保鲜，可加 `scrollBehavior: () => ({ top: 0 })` 补滚动位置。
- 路由无守卫——单用户自用可接受。

## 处理优先级

| 优先级 | 项 | 理由 |
|--------|-----|------|
| P0（已完成） | 启程时间误拦修复（#0）/ .npmrc 清理（#0） | 高危功能缺陷 + 工具链污染，已随本 ADR 落地 |
| P1（持续） | 类型单一来源收敛（#1） | gen:api 已入 check，重复声明是唯一「改一处忘一处必出错」的持续隐患 |
| P1（按需） | 健壮性缺口（#3：SSE abort / 轮询超时 / 地图降级 / 历史分页） | 用户可见的失败路径，随改动批次补 |
| P2（按需） | store 组织（#2）/ 死代码与重复（#4）/ 失效样式（#5） | 随 ADR-009 剩余页面迁移与功能迭代顺手清理 |
| P2（低） | 工具链收敛（#6） | ERESOLVE 仅警告不阻断，vfonts 一行移除 |
| 观察 | 非债项（#7） | 无外部消费者前不动作 |
