## 状态

**✅ 已采纳**——balance 概念保留并作为「用户记忆 → 决策」的算子定位；用户记忆走参数形态，落地遵循 ADR-004「把决策留给人」哲学契约与 ADR-012「自写优先，选择性引框架」原则。

## 一、背景

调整方案工具链收尾时，`adjust_days` 被删除（改天数能力由 suggest 多解列表天然覆盖），而 `balance_groups` 选择保留。保留的理由超越了「将来可能有用」的占位心态：**balance 是解决「个性化」这一核心命题的算子**。本 ADR 记录重新审视后的完整图景——balance 不只是均衡函数，它是「用户记忆 → 决策」链路上的执行器。

## 二、用户记忆 vs 对话记忆

| 维度 | 对话记忆 | 用户记忆 |
|------|---------|---------|
| 形态 | 文本（历史消息） | 参数（结构化数值/枚举） |
| 服务对象 | 对话连续性 | 决策质量 |
| 可计算性 | 不可（算法无法消费自然语言） | 可（直接进目标函数） |
| 可审计性 | 黑盒 | 结构化、可查看/编辑/清除 |
| 风险 | 易污染、token 成本 | 需设计维度、有冷启动 |
| 定位 | 辅（连续性） | 主（决策性） |

两者互补非替代：对话记忆保证「聊得下去」，用户记忆保证「算得准」。

## 三、闭环图景

```
对话记忆（素材）
    │  量化层：LLM 推断 + 映射兜底（estimate_stay 三层先例）
    ▼
用户记忆（个性参数向量：预算/节奏/偏好权重）
    │  balance 算子 / 目标函数（_LOAD_FUNCS 扩展位）
    ▼
方案 → 用户反馈（采纳/改参数）
    │  回流：反悔不污染长期记忆、稳定偏好沉淀
    ▼
用户记忆（更新）
```

## 四、balance 与记忆的契合

balance 是「记忆 → 决策」的算子：用户记忆中的参数（预算、体力节奏、时间窗偏好）经 balance 算子转化为均衡方案。`_LOAD_FUNCS` 已预留扩展位（当前仅 `stay` 一个实例），未来按个性参数维度扩展即可。

「遗留」标签是 balance 在产品新形态下的起点——它不是被遗忘的死代码，而是记忆消费端的第一个落点。

## 五、为什么量化 & 用户讨厌被量化吗

算法只能吃数字，不量化个性化就停留在话术层。用户讨厌的不是量化本身，而是「被量化背后的被决定感」：

- 被贴标签（「你是穷游党」）
- 被简化（一个数值覆盖复杂偏好）
- 无法修正（机器用错旧参数自作主张）

**关键契约（ADR-004 延伸）**：量化服务于「把决策留给人」——参数是建议输入而非判决；透明 + 可控时冒犯感消失。用户可查看、编辑、清除自己的参数。

## 六、边界清单

1. **可计算维度边界**：只有能进目标函数的维度才做参数记忆（预算/天数/节奏权重/时间窗偏好）；兴趣口味走对话与评语层。
2. **粒度边界**：记忆存长期稳定偏好；会话级临时决定走请求显式传参，防污染。
3. **覆盖优先级**：显式输入 > 记忆 > 兜底默认（复用 estimate_stay 三层结构）。
4. **透明可控边界**：可查看/编辑/清除，禁止隐式偷学。
5. **事实不可篡改**：营业时间/坐标是客观事实，记忆只调权重，不篡改事实。
6. **技术边界**：schema 从简；量化映射只在记忆更新时跑一次 LLM。

## 七、采集与冷启动

- 来源：对话推断（用户主动表达偏好）/ 行为观察（参数调整次数、方案采纳率）/ 显式表单。
- 新用户零参数：以默认参数 + 兜底映射起步，随使用逐步沉淀，不强迫首访填写。

## 八、更新与失效

- 漂移与反悔：临时决定（「这次想早点回」）不污染长期记忆——按会话隔离，仅稳定重复偏好沉淀。
- 失效机制：维度长期无确认或用户显式清除即失效。

## 九、评价标准与合规原则

- **评价标准**：方案采纳率、手动改参数次数下降、再次使用率（各列一条原则，量化指标 beta 后逐步定义）。
- **合规**：持久化个人数据需可删除；遵守《人工智能拟人化互动服务管理办法》（不向未成年人提供虚拟亲密关系服务，参 docs/slogan.md）。

## 十、落地原则

- 复用 estimate_stay 三层（显式 → LLM 推断 → 映射兜底）作为「用户语境转数值」的统一模板。
- 用户记忆与 balance 算子在 beta 后实施，不动当前已验证的求解链路。
- 遵循 ADR-004（决策留给用户）与 ADR-012（自写优先，选择性引框架）。
