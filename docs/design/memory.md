## 执行摘要

本文件是**规划蓝图**，不是决策记录。它记录"用户记忆 → 决策"链路的设计图景：balance 作为记忆消费端的首个算子，用户记忆以参数形态服务决策。具体落地遵循"决策留给用户"哲学与"自写优先、选择性引框架"。

## 背景

调整方案工具链收尾时，`adjust_days` 被删除（改天数能力由 suggest 多解列表天然覆盖），而 `balance_groups` 选择保留。保留理由超越了"将来可能有用"的占位心态：**balance 是解决「个性化」这一核心命题的算子**。本蓝图记录重新审视后的完整图景——balance 不只是均衡函数，它是「用户记忆 → 决策」链路上的执行器。

## 总体目标

- **用户记忆 = 参数形态**：长期稳定偏好以结构化参数存储（可计算、透明、可控），服务决策而非陪伴。
- **balance = 记忆消费端算子**：用户个性参数经 balance 转化为均衡方案。
- **量化层**：把对话语境转成个性参数（LLM 推断 + 映射兜底）。

## 核心设计

### 用户记忆 vs 对话记忆

| 维度 | 对话记忆 | 用户记忆 |
|------|---------|---------|
| 形态 | 文本（历史消息） | 参数（结构化数值/枚举） |
| 服务对象 | 对话连续性 | 决策质量 |
| 可计算性 | 不可 | 可（直接进目标函数） |
| 可审计性 | 黑盒 | 结构化、可查看/编辑/清除 |
| 风险 | 易污染、token 成本 | 需设计维度、有冷启动 |
| 定位 | 辅（连续性） | 主（决策性） |

两者互补非替代：对话记忆保证"聊得下去"，用户记忆保证"算得准"。

### 闭环图景

```
对话记忆（素材）
    │  量化层：LLM 推断 + 映射兜底
    ▼
用户记忆（个性参数向量：预算/节奏/偏好权重）
    │  balance 算子 / 目标函数
    ▼
方案 → 用户反馈（采纳/改参数）
    │  回流：反悔不污染长期记忆、稳定偏好沉淀
    ▼
用户记忆（更新）
```

### balance 与记忆的契合

balance 是「记忆 → 决策」的算子：用户记忆中的参数经 balance 转化为均衡方案。函数注册表已预留扩展位（当前仅停留时间一个实例），未来按个性参数维度扩展。

### 为什么量化（用户讨厌被量化吗）

算法只能吃数字。用户讨厌的不是量化本身，而是"被量化背后的被决定感"（被贴标签 / 被简化 / 无法修正）。关键契约：量化服务于"把决策留给人"——参数是建议输入而非判决；透明 + 可控时冒犯感消失。

### 边界清单

1. 只有能进目标函数的维度才做参数记忆；兴趣口味走对话与评语层。
2. 记忆存长期稳定偏好；会话级临时决定走显式传参，防污染。
3. 覆盖优先级：显式输入 > 记忆 > 兜底默认。
4. 可查看 / 编辑 / 清除，禁止隐式偷学。
5. 客观事实不可篡改，记忆只调权重。
6. 量化映射只在记忆更新时跑一次 LLM。

### 采集与冷启动

来源：对话推断 / 行为观察（参数调整次数、方案采纳率）/ 显式表单。新用户零参数，以默认参数 + 兜底映射起步，不强迫首访填写。

### 更新与失效

临时决定按会话隔离，不污染长期记忆；仅稳定重复偏好沉淀。维度长期无确认或用户显式清除即失效。

### 评价与合规

评价标准：方案采纳率、手动改参数次数下降、再次使用率。合规：持久化个人数据需可删除；遵循相关管理办法。

## 核心决策速览

- balance 是"用户记忆 → 决策"链路上的算子。
- 用户记忆走参数形态，透明可控，服务决策。
- 量化服务于"把决策留给人"，非判决。
- 复用 estimate_stay 三层结构作为"用户语境转数值"统一模板。

## 风险与取舍

| 风险 | 已做取舍 |
|------|---------|
| 被量化背后的被决定感 | 参数为建议输入、可查看/编辑/清除 |
| 记忆污染（临时决定写入长期） | 按会话隔离，仅稳定偏好沉淀 |
| 冷启动无参数 | 默认参数 + 兜底映射起步 |
| 引入复杂记忆框架 | 自写参数形态，不引框架（自写优先） |
