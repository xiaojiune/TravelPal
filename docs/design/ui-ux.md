## 执行摘要

本文件是**设计蓝图 / 模式沉淀**，不是决策记录。它沉淀前端可复用的设计模式，并记录对外部 AI 助手方案的取舍（已实现 / 可评估 / 不引）。具体"为什么这么选"见关联 ADR。

## 背景

首页主页面 UI/UX 重设计完成。复盘发现前端难度不在语法而在 UI/UX 设计：一次视觉调整牵扯大量状态逻辑（手风琴展开 / 景点卡展开 / 编辑态 / 三绿 / 计数）。为沉淀方法论、避免后续页面重复踩坑，将设计模式与外部方案取舍落档。

## 核心发现：设计从状态机反推

视觉决策不是孤立样式，而是与状态逻辑强耦合。首页重设计的本质是把「用户完成三件事」的流程翻译成可观测、可推进的状态机：

```
用户心智            →  状态机
填了城市           →  cityGreen
酒店拉取成功       →  hotelGreen
添加了景点         →  spotsGreen
三绿齐备           →  allGreen → 生成按钮青绿
景点参数没填全     →  warnCount !N
```

结论：**先定义状态语义，再设计视觉反馈**——视觉只是状态的投影，状态不明则视觉必然反复返工。

## 总体目标

- 沉淀可复用设计模式，避免后续页面重复踩坑。
- 明确外部方案的**三类边界**：已实现 / 可评估 / 不引。
- 为 Agent-driven UI 预留（SchemaFormCard 表单渲染器、A2UI 协议观察）。

## 关键决策

1. **状态语义先于视觉**：先定状态机再设计反馈，避免反复返工。
2. **自写优先，选择性引组件库**：A2UI 等声明式库不引 renderer（无 Vue 官方实现，自写即违反原则），已有自写 mini-catalog。A2UI 仅作协议观察。
3. **编辑即确认**：删除"确认按钮"，改为即时回写 + 短反馈。
4. **黄 !N 而非红 !**：待补充用黄 + 计数，红色留给真正错误。
5. **氛围动画克制**：只保留状态切换微动效。

## 核心决策速览

- 状态语义先于视觉。
- 自写优先、选择性引组件库（不引 A2UI renderer）。
- 编辑即确认（即时回写）。
- 黄 !N 而非红 !（待补充≠错误）。
- 氛围动画克制。

## 风险与取舍

| 风险 | 已做取舍 |
|------|---------|
| 视觉与状态耦合，改动易互相影响 | 先定义状态机再设计反馈 |
| 引入声明式 UI 库 | 不引 renderer，自写 mini-catalog；A2UI 仅协议观察 |
| 动效成本高 | 仅保留状态切换微动效，氛围动画克制 |
