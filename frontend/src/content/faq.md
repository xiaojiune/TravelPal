## TravelPal 是什么？
1、不占有的陪伴，不缺席的可靠——这是 TravelPal 的项目哲学。

2、项目源自我的毕设《基于带时间窗旅行商问题的旅游路径规划》的visualization（可视化）分支，历经多轮重构与优化。宽泛地说，它会是一个旅游出行方面的C端产品（未实现）。

3、它的定位是把计算交给机器、把决策留给你：你不必为了规划一次旅行去翻攻略、核营业时间、算车程。从「一句话想去哪」到「每一步怎么走」，TravelPal 负责繁琐的体力活，把选择权始终留给你。

## 关于项目你可能想了解的

### 数据从哪来？

基于高德地图API，理论上支持所有可被查找的“点”及可被解析的信息

### 行程如何得到的？

引擎层基于自实现的CA/VNS的元启发式算法（未引入其它求解框架）

### 如何开始？

① 填城市 → ② 填酒店并搜索确认坐标 → ③ 添加想去的景点 → ④ 点击「生成最优行程」。也可以直接在 AI 助手里用对话描述需求。

### 整个项目是如何实现的？有哪些技术？

后端：FastAPI + LangGraph + Celery + PostgreSQL + Redis

前端：Vue3 + TypeScript + Naive UI（组件库）

其它：Docker、CI/CD

### 项目就这些功能吗？

1、当前版本聚焦确定性规划 —— 输入城市/酒店（必需）/景点（≥1）等参数，输出旅游时间安排表及地图显示。

2、项目遵循“依赖倒置”思维，架构足以快速承接未来多种功能接入，欢迎在问卷中填下您需要的功能或建议。

## 它和市面上的软件有什么区别？

### 基础设施与平台（高德地图、携程、飞猪）

它们是地图数据与交易平台。TravelPal 不替代它们，而是站在它们的生态之上做「规划决策」——用高德的坐标和路网数据，解决「该去哪、什么顺序去」。

### 商业与主流软件（马蜂窝、穷游、Stardrift、TripIt）

大多是攻略内容社区或行程管理工具，靠内容聚合与人工整理，不对景点顺序、营业时间做约束求解，生成的是「建议」而非「可执行的方案」。

### 开源与 AI Agent 项目（智旅云图、TripStar 旅途星辰）

同走对话式 AI 路线，但多为 LangChain + RAG 拼接 （+MCP） 生成文字与图片攻略，样式非常丰富且高级，伴随着”不确定性“。TravelPal 与之不同：用 CA/VNS 真正求解路线，把营业时间、停留时长、驾车耗时纳入约束，产出的是经算法验证的可执行行程。
